# Вход через Telegram

На сайте кнопка входа создаёт серверную попытку на пять минут и открывает чат бота. В боте нужно нажать Start, сравнить шестизначный код с кодом в окне игры и явно подтвердить вход. Сайт проверяет подтверждение раз в две секунды и остаётся в исходном окне. Этот путь не использует домен Telegram Login Widget, поэтому ошибка `Bot domain invalid` не блокирует регистрацию.

Mini App по-прежнему проверяет HMAC подписанных `initData`, срок, пользователя и защиту от повторного использования. Идентификатор аккаунта общий: `identity:telegram:<user id>`. Старый callback официального виджета поддерживается для совместимости.

Попытка веб-входа содержит случайный публичный ID, отдельный секрет опроса, привязку к исходному домену и идентификатору устройства, срок и статус. Сервер хранит хеш секрета. Открытие бота не авторизует игрока: требуется callback от живого пользователя в личном чате. Webhook проверяет `X-Telegram-Bot-Api-Secret-Token` до обработки тела. Секрет по умолчанию детерминированно выводится SHA-256 из серверного bot token с отдельным префиксом; дополнительно поддерживается `TELEGRAM_WEBHOOK_SECRET`. Подтверждение однократное, погашение и создание сессии защищены атомарной проверкой. Неподтверждённая попытка не создаёт аккаунт. Origin и CSRF обязательны для начала и опроса; частый приватный опрос не расходует общий лимит попыток регистрации.

Секрет попытки и исходный fingerprint сохраняются в sessionStorage для восстановления после перезагрузки и смены ориентации экрана. Без хранилища вход продолжает работать в памяти. Закрытие окна прекращает опрос, отменяет текущий запрос и не принимает его запоздавший session token. Ошибка сети повторяется, истёкший запрос предлагает начать заново. При блокировке всплывающего окна остаётся явная ссылка «Продолжить вход в Telegram».

## Настройка

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `APP_ORIGIN` задаются только на сервере. В Git и клиентскую сборку токен не попадает. `scripts/configure-telegram.mjs` принимает приватный JSON через неотображаемый stdin. Поля `menuUrl` и `webhookUrl` настраивают HTTPS-кнопку Mini App и webhook с секретным заголовком и обновлениями `message`, `callback_query`. Pending updates не удаляются. Значение токена не передаётся в argv и не печатается в логах.

Проверки: `telegram-bot-login.test.mjs` исполняет настоящий клиент, API и webhook с локальным адаптером Bot API; проверяет явное подтверждение, общий аккаунт с Mini App, ложный webhook, приватный секрет, время, reload, сеть и закрытие во время запроса. `client-auth.test.mjs` и `telegram-miniapp.test.mjs` сохраняют проверки SDK, отсутствия cookies/sessionStorage и совместимости старого виджета. `check:worker` проверяет тот же сценарий в собранном Worker с реальной SQLite. Эти проверки не отправляют сообщения реальным пользователям и не запускают браузер.
